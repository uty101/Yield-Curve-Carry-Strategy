## Not verified

- `git_commit()` stamps the report with the commit **before** this commit
  exists, because the report is written and then committed. The header
  therefore names the parent commit, not the one the file lands in. Fixing it
  would mean writing the report twice per commit. Stated here rather than
  hidden; the `config_hash` in the same line is exact.
- `test_readme_has_no_number_outside_the_block` strips code spans and links
  before looking. A result-shaped number typed inside backticks outside the
  block would not be caught. That is a deliberate hole — the README's prose
  names config keys and file paths — and the block is where results live.

## Open

- `make run` is not idempotent: `reports/specifications.csv` is append-only
  and every `run --all` adds 11 rows, which changes N and therefore every DSR
  in the report. The Makefile says so in a comment and `make all` is `build`
  plus `report` only. There is no guard in code, because a guard would be a
  rule that some runs do not count, and rule 6 says the opposite.
