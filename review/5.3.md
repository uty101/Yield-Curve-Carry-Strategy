**The headline, and it was fixed before these numbers were seen**
(amendment 1, written into `PLAN.md` 5.3 and `CLAUDE.md` in commit
`c77be42`, which precedes every commit that computes anything):
`carry_hedged`, `full` window, `r_net`.

**Three decisions this step made that the plan left open**, all visible in
the module docstring:

1. **Availability is applied before sizing, not after.** The plan says a
   bucket with a NaN return "is not held". Dropping it after the legs were
   sized would leave `Σ wd ≠ 0`. It is instead marked ineligible in the
   signal frame, and the weights are built on what remains, so neutrality
   survives.
2. **A flat month still gets a row.** A month the 5.2 minimum flattens earns
   0 and is charged the cost of coming out of last month's book. Silently
   omitting it would shorten the sample and hide the exit cost.
3. **`exclude_buckets` (for the 5.5 GB-30y variant) is part of the variant
   definition in `VARIANTS`, not a config knob.** Adding a knob to
   `config.toml` that PLAN.md never named would breach rule 14; the
   exclusion is instead recorded in the spec-log `note` as JSON, like an
   override.

**One bug found and fixed while writing the tests.** `max_drawdown` first
took the running peak as `wealth.cummax()`, which starts at the first
month's wealth — so a series that falls in its first month showed a
drawdown of 0. The running peak now starts at **1.0, the level at
inception**, which is what the plan's own closed-form test asks for
(`−10%` then `+5%` → `−0.10`). A peak at inception has no date in the
series and `dd_peak` is then an empty cell.

## Session 5 fix 2 — duration neutrality is not currency neutrality

**The caveat, stated plainly and to be carried into the report wherever an
unhedged number appears.** *The book is neutral in **duration**. It is not
neutral in **notional**, and notional is what carries currency risk. Every
unhedged variant in this project is, to 95% of its variance, a currency
book with a small bond position attached; its Sharpe should never be read
beside the hedged book's as though the two were the same strategy measured
two ways.*

`data/checks/unhedged_fx_exposure.csv` (session-5 fix 2) is the evidence:
the net notional per currency per month for each of the three unhedged
runs, the FX return it was exposed to and the contribution, then a second
block with the regression of each book's monthly return on its own
currency-weighted FX term.

> Claim: 95% of the unhedged carry book's monthly return variance is its own currency exposure.
> Number: regressing `carry_unhedged`'s monthly gross return on its currency-weighted FX return gives **R² = 0.953**, beta 0.956 and an annualised intercept of **−0.56%**. The correlation is 0.976. Run the same FX term against the **hedged** book and the correlation is −0.195, which is what the hedge is for. Monthly standard deviations: the FX term 3.261%, the unhedged book 3.196%, the hedged book 0.644% — the currency term is more volatile than the whole unhedged book.
