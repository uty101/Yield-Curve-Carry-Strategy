# Review — Step 0.2 — Raw data manifest

Date: 2026-09-16   Commit: (next commit)   Tests: 17/17

## What changed
- `src/curvecarry/manifest.py` — `raw_path(source, name, ext, fetched, root)` → `root/source/<name>_<YYYYMMDD>.<ext>`; `write_raw(content, path, url, source, manifest)` refuses an existing path with `FileExistsError`, writes the bytes, appends `{source, name, path, url, sha256, bytes, fetched_at}` to the manifest list; `fetch_bytes(url, *, params, headers, timeout)` — the only `requests` call in the package, browser User-Agent, `raise_for_status`, `RuntimeError("empty body")` on zero bytes; `latest_raw(source, name, root)`.
- Rulings from issue #4 applied: `latest_raw` globs `name_*.*` and raises `ValueError` naming the extensions if more than one is present; "newest" is the `YYYYMMDD` in the filename, not mtime; the manifest `name` is the stem with `_YYYYMMDD` removed (inverse of `raw_path`), and a path without that suffix is refused.
- `data/raw/manifest.json` — `[]`, committed.
- `tests/test_manifest.py` — the plan's 4 tests plus `test_latest_raw_refuses_mixed_extensions` (#4), `test_manifest_name_round_trips_raw_path` (#4), `test_fetch_bytes_is_the_only_requests_call`, `test_fetch_bytes_rejects_empty_body` (monkeypatched, no network).
- `CLAUDE.md` — invariant 5 now names `test_second_fetch_to_existing_path_raises`, `test_refetch_gets_dated_filename`.
- `PLAN.md` not edited; the #4 rulings are recorded there only by reference (see Open).

## Not verified
- `fetch_bytes` against a live URL: by rule 12 no test touches the network; the first real call is step 1.1's `fetch`. Settled by that step's manifest entry.
- `latest_raw` when two files share a date and extension: `write_raw` makes that impossible on one machine (it refuses the path), but a copied-in duplicate with a different case on a case-insensitive filesystem is not guarded. Settled by never hand-copying into `data/raw/`.
