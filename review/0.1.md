**One deviation from the plan, stated in full.** PLAN.md defines
`run_id = f"{timestamp_utc:%Y%m%dT%H%M%S}-{config_hash}"`. Two runs of the
same config inside one second — which `run --all` (5.3) will produce — get
the same id, and the plan's own `test_log_run_appends_row` requires distinct
ids. `log_run` therefore appends `-2`, `-3`, … when the id already exists in
the file. The first run in a second keeps the plan's exact format.
`test_same_second_same_config_gets_distinct_ids` guards it.
