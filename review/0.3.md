## What changed
- `tests/test_reviews.py::test_reviews_follow_template` — parametrised over every `review/*.md` except `TEMPLATE.md`; asserts the first line matches `# Review — Step \d+\.\d+ — `, a `Date: … Commit: … Tests: \d+/\d+` line in the first 5 lines, the five headings, and that every `> Claim:` block is followed by a `> Number:` line and at least 5 `> ` row lines (the `> Rows (...)` label line is not counted as a row). Passes vacuously with no reviews (a `None` parameter).
- `scripts/make_fixture.py` — `make_fixture(source, raw, *, sheet, header_lines, fixtures)` and the CLI `python scripts/make_fixture.py <source> <raw_path> [--sheet NAME] [--header-lines N]`; writes header rows + first 50 data rows to `tests/fixtures/<source>/<name>.<ext>` with the `_YYYYMMDD` fetch date stripped from the name (`DGS10_20260916.csv` → `DGS10.csv`, so Phase 1's fixture paths read as the plan names them); csv and xlsx only, the xlsx output has one sheet under the source's sheet name.
- `tests/test_reviews.py::test_make_fixture_trims_to_50_rows` — a 200-row csv and a 200-row two-sheet xlsx → 51 lines / 51 rows each, header first, first and 50th data rows checked, unsupported extension refused.
- `CLAUDE.md` — invariant 12's cell now names `test_reviews_follow_template` for the review side (the network side stays `review`).
- **Implementation detail the plan leaves open, stated here:** the plan says "header rows plus the first 50 data rows" without saying how the script knows how many header rows a source has (FRED 1, MOF 2, the Bundesbank API about 5). `--header-lines N`, default 1, is that knob. It affects fixtures only, never a result.
